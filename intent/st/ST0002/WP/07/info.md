# WP-07: Developer ID signing and notarisation

## Objective

Sign and notarise every macOS binary pplr ships with hv's Geodica Developer ID, through a signer that is project code, so that every release build is signed and checkable.

**Scope**

- **The signer**: `bin/.devbin/cmd/macos`, in bash or zsh, ported from Intent's (which was ported from Lamplight's). No Python, so Ccusage's `tools/sign-macos` is out. It uses "Developer ID Application: Geodica Pty Ltd (76BQL8L47U)", the hardened runtime, a secure timestamp and the identifiers WP01 settles.
- **What it signs**:
  - `pplr`;
  - `pplr-contacts`;
  - the `Pplr Links.app` that `pplr handler --install` builds, which ST0001 WP08 calls this step for in place of `codesign --sign -`.
- **Notarisation** with `notarytool`, using a keychain profile on rhadamanth. A bare binary is notarised but never stapled, as in Intent.
- **Checks**: `codesign --verify --strict -R <requirement>` and `spctl -a -t open --context context:primary-signature`, as Intent does. Doctor reports the same verdict for the running tree on macOS.
- **Where it runs**: on rhadamanth only, never on CI. It is wired into the release so the macOS assets are signed before `release attach` (E3).
- **Proof on a scratch build**: a signed, notarised build that passes every check. Nothing is published.

**Criteria**: AC-07.1 and AC-07.2.

**Depends on**: WP01, and ST0001 WP09 for the sidecar.
