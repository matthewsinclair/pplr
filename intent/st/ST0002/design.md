# ST0002 design: Pplr through Homebrew

Design record by vc, 2026-11-02, revised the same day with hv's answers. It draws on a survey of Cldr, Ccusage, Intent and devbin 0.1.19, dc's boot findings and cc's survey. ST0001 builds the binary; this thread makes Homebrew the way it reaches a machine. ST0001's recon (`recon.md` on ST0001) carries the Pplr facts this rests on.

## 1. Rulings (hv, 2026-11-02)

1. **Everything is signed** with hv's Geodica Developer ID, whether or not anything needs it today. For pplr that is every macOS binary it ships: `pplr`, the `pplr-contacts` sidecar, and the `Pplr Links.app` that `pplr handler` builds.
2. **dc runs the release cut, with hv's approval.**
3. **The tap exists**: `matthewsinclair/homebrew-pplr`, created by hv, empty. Its description reads "Homebrew tap for cldr" and needs correcting.
4. **kovacs is ready** as the Linux leg.
5. **Targets are Intent's set** (hv, 2026-11-02, on dc's WP01 record): `aarch64-apple-darwin`, `x86_64-unknown-linux-musl` and `aarch64-unknown-linux-musl`. Intel macOS is dropped. This settles E1.
6. **One neutral set of notary credentials**, `geodica.apple.*`, used by pplr and later shared with Intent. Creating the keychain entries is interactive, so it is hv's. Renaming Intent's entries is an Intent change, out of scope here.
7. **`Pplr Links.app` ships prebuilt and signed** in every macOS tree, and `handler --install` only registers it (ST0001 design 3.4).

## 2. The contract

**Pplr joins devbin's dev/opt/brew contract**, `~/Devel/prj/Devbin/docs/dev-opt-brew.md` (T1 to T10), as Molt, Utilz, Intent and devbin already do. dc proposed it, and devbin's release flow expects it. **Intent is the worked example to follow**: it ships signed, notarised bare binaries through an `assets` formula under the same contract. Applied to pplr:

| Item | What it means for pplr                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T1   | **Three trees**: dev (the checkout), opt (a prefix the maintainer names, with no default) and brew (`$(brew --prefix)/opt/pplr/libexec`).<br>A tree holds `<root>/bin/pplr`, `<root>/bin/pplr-contacts` on macOS, and the manifest. Templates, icons and the README are inside the binary (ST0001 D6).<br>The binary finds its root from its resolved path. One function lists the runtime set, and install and doctor both read it.                                                            |
| T2   | **`pplr install [--prefix <dir>] [--force]` publishes from dev to opt only.**<br>It refuses a dirty runtime set: the build inputs from cargo's dep-info, plus the sidecar source.<br>It replaces a prefix only with `--force`, and only when the manifest says pplr wrote it.<br>`install` never writes the brew tree: as T2 allows for signed assets, the formula lays the signed binaries out and writes the manifest itself.                                                                 |
| T3   | **The manifest is `<root>/.pplr-install`.** Its header carries `# tool`, `# version`, `# source_commit` (the full sha the binaries were built from) and `# managed_by`. Its body has one `shasum -a 256 -c` line per runtime file, sorted with `LC_ALL=C sort`. In opt and brew, doctor checks it and names each drifted file.                                                                                                                                                                  |
| T4   | **One function names the tree**: brew, opt, dev or unknown.<br>`pplr --version` and `pplr version` print `pplr <version> (<tree>, <sha12>[+dirty])`. The commit and the dirtiness are stamped into the binary at build time, and one provenance word (`release` or `dev`) may follow the closing parenthesis.<br>Doctor prints the same line.                                                                                                                                                   |
| T5   | **`pplr use [dev\|opt\|brew]`.** The link set is `pplr` alone, in `~/.local/bin`; the sidecar is never linked. `use brew` removes the link, and refuses when no brew copy would answer. Doctor runs the shadow check.                                                                                                                                                                                                                                                                           |
| T6   | **No upgrade verb.** The docs give the steps per tree: in dev, `git pull` and build; in opt, `pplr install --force` from dev; in brew, `brew upgrade pplr`.                                                                                                                                                                                                                                                                                                                                     |
| T7   | **pplr has no test or lint verbs** (devbin's `test` and `check` are the project's), so it has nothing to refuse. Recorded, not built.                                                                                                                                                                                                                                                                                                                                                           |
| T8   | **The formula is rendered, never typed**: from `packaging/homebrew/pplr.rb` by `bin/devbin formula`, in `assets` mode, taking the version and each asset's sha256 from the release.<br>`install` lays the binaries out in `libexec` with mode 0755, writes the T3 manifest with `managed_by: brew`, verifies each signature against its designated requirement, and links `pplr` into `bin`.<br>The caveats name `pplr use`. `test do` verifies the signatures again and runs the version line. |
| T9   | devbin only: not applicable.                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| T10  | **The proof**: on rhadamanth, `use dev`, `use opt` and `use brew`, each followed by the version line, doctor and the shadow check; on kovacs, brew alone. Every brew probe is prefixed with `HOMEBREW_NO_AUTO_UPDATE=1`.                                                                                                                                                                                                                                                                        |

## 3. Decisions

| ID  | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Why                                                                                                                                                                                                        |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| E1  | **An `assets` formula** (devbin's `formula: mode: assets`, as Intent's): release assets per target, each with its sha256 taken from the release's `SHA256SUMS`.<br>The macOS assets hold `pplr` and `pplr-contacts`, both signed and notarised. The Linux assets hold `pplr` alone.<br>The targets are ruling 5's.                                                                                                                                                                                                                                                                                                                                                                                                           | Ruling 1. A keg cannot build signed binaries from source, so the formula installs what was signed.                                                                                                         |
| E2  | **Developer ID signing and notarisation for every macOS binary**, with "Developer ID Application: Geodica Pty Ltd (76BQL8L47U)":<br>- each binary has a fixed identifier (eg `com.geodica.pplr`, `com.geodica.pplr-contacts`; WP01 settles them);<br>- the hardened runtime and a secure timestamp;<br>- notarised with `notarytool`;<br>- verified with `codesign --verify --strict -R <requirement>` and `spctl`, as Intent does.<br>Signing runs on rhadamanth, where the identity lives, never on CI. The signer is project code in bash or zsh: `bin/.devbin/cmd/macos`, ported from Intent's, which was itself ported from Lamplight's. Ccusage's signer is Python, which rules it out.                                | Ruling 1. A stable designated requirement also keeps the Contacts and Automation grants stable across upgrades.                                                                                            |
| E3  | **devbin's release core cuts every release** (devbin `^0.1.19`):<br>- `release.repo: matthewsinclair/pplr`;<br>- `remotes: [local, upstream]`, the Dropbox bare repo then GitHub, which is devbin's standard shape;<br>- the gates `check all`, `test all` and `doctor`, the kovacs leg, and CI on `candidate/<tag>`;<br>- the notes kind `changelog`;<br>- the release assets built by a CI workflow (`assets.workflow`), with the macOS ones signed and notarised by `bin/devbin macos`, then attached by `bin/devbin release attach --from <dir>`, which writes `SHA256SUMS`;<br>- `after: [bin/devbin formula publish]`.<br>WP01 settles the exact order of build, sign, attach and publish, following Intent's release. | One release sequence shared with every devbin project, not a bespoke `tools/release`.                                                                                                                      |
| E4  | **The version lives in `Cargo.toml`** (`version_from: Cargo.toml`). The release owns `Cargo.lock` through a `derived:` step, `bin/devbin lock-sync` (`bin/.devbin/cmd/lock-sync`): zsh, modelled on Gtools', which rewrites the lock and prints `Cargo.lock`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                | devbin refuses `Cargo.lock` as a sidecar, and ST0001 D7 makes `Cargo.toml` the only version source.                                                                                                        |
| E5  | **The tap is `matthewsinclair/homebrew-pplr`**, with its description corrected to "Homebrew tap for pplr". It carries a `test.yml` adapted from homebrew-ccusage's, which on macOS and Ubuntu runs `brew style`, `brew audit --strict`, `brew install`, and `brew test` with the signature check.                                                                                                                                                                                                                                                                                                                                                                                                                            | Every tool's tap follows this convention, and devbin's formula tool derives the tap's name from it by default.                                                                                             |
| E6  | **CI is `.github/workflows/tests.yml`**, firing on `main` and `candidate/**` and hardened in house style: `permissions: contents: read`, actions pinned by sha, `persist-credentials: false`, `fail-fast: false`, timeouts. It runs the cargo gates and the bats suite against the Rust binary on macOS and Linux. A separate workflow builds the release assets from the tag.                                                                                                                                                                                                                                                                                                                                               | devbin's pre-flight refuses a cut unless pushing `candidate/<tag>` starts `ci.workflow` (default `tests.yml`). ST0001 WP02 builds `tests.yml`; this thread adds the candidate trigger and the asset build. |
| E7  | **The CHANGELOG opens each release as `## [X.Y.Z] - unreleased`**, starting with 2.0.0.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | devbin's default `changelog` notes kind reads that heading, not `## [Unreleased]`.                                                                                                                         |
| E8  | **Outward-facing steps happen only in WP06**: no tag, push, release, notarisation of a release build, or tap write before then. In WP06, dc runs each outward step with hv's approval. Earlier work proves the path on a scratch clone and a scratch tap.                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | These steps are outward-facing and hard to reverse.                                                                                                                                                        |

## 4. What the binary must provide

ST0001 builds the commands. This thread needs these from the binary, built in WP03 on ST0001's scaffold:

- the resolved root and the tree function (T1, T4);
- `install` and `use` (T2, T5), and the manifest (T3);
- the version line, with the build commit and dirtiness stamped in (T4);
- doctor rows for the tree, the manifest, the shadow check and, on macOS, each binary's signature, added to ST0001's doctor;
- `handler --install` naming the opt link under brew (ST0001 WP08), and the app it builds signed with the Geodica identity instead of today's ad-hoc `codesign --sign -` (WP07 provides the signing step);
- `help --details` from the embedded README (ST0001 D6).

## 5. Migration on rhadamanth

- Today `~/.local/bin/pplr` links to the checkout's bash dispatcher. After 2.0.0, `brew install` followed by `pplr use brew` removes that link, and doctor's shadow check confirms brew answers.
- `setup.sh` and `.env.example` go in ST0001 WP13. Any of these in the user's shell configuration lives in Molt-matts, not here: `PPLR_ROOT`, `PPLR_BIN_DIR`, or the checkout's `bin/` on `PATH`. Doctor names it, and Molt-matts makes the fix.
- The Contacts grant moves from the terminal-run legacy engine to the signed `pplr-contacts`. WP06 records whether macOS asks again, and confirms that a `brew upgrade` does not.
- None of this touches the People tree.
