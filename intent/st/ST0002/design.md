# ST0002 design: Pplr through Homebrew

Design record by vc, 2026-11-02, from a survey of Cldr, Ccusage and devbin 0.1.19, dc's boot findings and cc's survey. ST0001 builds the binary; this thread makes Homebrew the way it reaches a machine. ST0001's recon (`recon.md` on ST0001) carries the Pplr facts this rests on.

## 1. The contract

**Pplr joins devbin's dev/opt/brew contract**, `~/Devel/prj/Devbin/docs/dev-opt-brew.md` (T1 to T10), as Molt, Utilz, Intent and devbin already do. dc proposed it, and devbin's own release flow expects it: after a cut it tells the maintainer to run `brew upgrade` and `<tool> use brew` and expects the version line. Applied to pplr:

| Item | What it means for pplr                                                                                                                                                                                                                                                                                                                                                                                          |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T1   | Three trees: dev (the checkout), opt (a prefix the maintainer names; no default), brew (`$(brew --prefix)/opt/pplr/libexec`). A tree is `<root>/bin/pplr`, `<root>/bin/pplr-contacts` on macOS, and the manifest; templates, icons and the README are inside the binary (ST0001 D6). The binary finds its root from its resolved path. One function lists the runtime set, and install and doctor both read it. |
| T2   | `pplr install [--prefix <dir>] [--force] [--managed-by brew]` publishes from dev only, refuses a dirty runtime set (the build inputs, from cargo's dep-info, plus the sidecar source), replaces a prefix only with `--force` and only when the manifest says pplr wrote it.                                                                                                                                     |
| T3   | The manifest is `<root>/.pplr-install`: `# tool`, `# version`, `# source_commit` (the full sha the binaries were built from), `# managed_by`, then one `shasum -a 256 -c` line per runtime file, sorted with `LC_ALL=C sort`. Doctor in opt and brew checks it and names each drifted file.                                                                                                                     |
| T4   | One function names the tree: brew, opt, dev or unknown. `pplr --version` and `pplr version` print `pplr <version> (<tree>, <sha12>[+dirty])`, with the commit and dirtiness stamped into the binary at build, and may add one provenance word (`release` or `dev`) after the parenthesis. Doctor prints the same line.                                                                                          |
| T5   | `pplr use [dev\|opt\|brew]`. The link set is `pplr` alone, in `~/.local/bin`; the sidecar is never linked. `use brew` removes the link and refuses when no brew copy would answer. Doctor runs the shadow check.                                                                                                                                                                                                |
| T6   | No upgrade verb. The docs give the steps per tree: dev `git pull` and build, opt `pplr install --force` from dev, brew `brew upgrade pplr`.                                                                                                                                                                                                                                                                     |
| T7   | pplr has no test or lint verbs (devbin's `test` and `check` are the project's), so nothing to refuse. Recorded, not built.                                                                                                                                                                                                                                                                                      |
| T8   | The formula is rendered from `packaging/homebrew/pplr.rb` by `bin/devbin formula`, never typed. `install` builds, then runs `pplr install --prefix libexec --managed-by brew` and links `pplr` into `bin`. The caveats name `pplr use`. `test do` runs the version line.                                                                                                                                        |
| T9   | devbin only: not applicable.                                                                                                                                                                                                                                                                                                                                                                                    |
| T10  | The proof: `use dev`, `use opt`, `use brew` on rhadamanth, each followed by the version line, doctor and the shadow check; brew alone on Linux (kovacs). Every brew probe prefixed `HOMEBREW_NO_AUTO_UPDATE=1`.                                                                                                                                                                                                 |

## 2. Decisions

| ID  | Decision                                                                                                                                                                                                                                                                                                                                                                                                                | Why                                                                                                                                                                                                             |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| E1  | **A source-build formula**, devbin's `formula: mode: source`: a git url with exactly one `@@TAG@@` and one `@@REVISION@@`, `depends_on "rust" => :build`, `cargo install`-style build, and on macOS the sidecar compiled with the `swiftc` from the Command Line Tools that Homebrew already requires. Linux builds without the sidecar.                                                                                | It is devbin's and Cldr's pattern, and Utilz's (dc). `github.com/matthewsinclair/pplr` is public and MIT licensed. Ccusage's signed tarballs exist for Keychain access, which pplr does not use.                |
| E2  | **No Developer ID signing**: the linker's ad-hoc signature only. Contacts and Automation grants land on the terminal that runs pplr, as Cldr's Full Disk Access grant does. ST0002's acceptance includes a check that the grant survives a `brew upgrade`; signing comes back only if that check fails.                                                                                                                 | Signing adds a keychain identity, notarisation and project code with no benefit when the grant is the terminal's. The check makes the assumption testable.                                                      |
| E3  | **Releases are cut by devbin's release core**, devbin `^0.1.19`, `commands.release.enabled: true`: `release.repo: matthewsinclair/pplr`; `remotes: [local, upstream]` (the Dropbox bare repo, then GitHub), as devbin's own standard shape; gates `check all`, `test all` and `doctor`; the kovacs leg; CI on `candidate/<tag>`; notes kind `changelog`; release object `local`; `after: [bin/devbin formula publish]`. | One release sequence shared with every devbin project, rather than Cldr's or Ccusage's bespoke `tools/release`. Ccusage's tooling is Python, which rules it out anyway.                                         |
| E4  | **The version lives in `Cargo.toml`** (`version_from: Cargo.toml`). The release owns `Cargo.lock` through a `derived:` step, `tools/lock-sync`, written in zsh after Gtools' model, which rewrites the lock and prints `Cargo.lock`.                                                                                                                                                                                    | devbin refuses `Cargo.lock` as a sidecar; ST0001 D7 makes `Cargo.toml` the only version source.                                                                                                                 |
| E5  | **The tap is `matthewsinclair/homebrew-pplr`**, new, with a `test.yml` copied from homebrew-cldr's: `brew style`, `brew audit --strict`, `brew install --build-from-source` and `brew test`, on macOS and Ubuntu.                                                                                                                                                                                                       | The convention every tool follows; devbin's formula tool derives it by default. The repository does not exist yet: creating it is hv's.                                                                         |
| E6  | **CI is `.github/workflows/tests.yml`**, firing on `main` and `candidate/**`, hardened in house style (`permissions: contents: read`, actions pinned by sha, `persist-credentials: false`, `fail-fast: false`, timeouts), running the cargo gates and the bats suite against the Rust binary on macOS and Linux.                                                                                                        | devbin's pre-flight refuses a cut unless pushing `candidate/<tag>` starts the workflow it reads (`ci.workflow`, default `tests.yml`). ST0001 WP02 builds this workflow; this thread adds the candidate trigger. |
| E7  | **The CHANGELOG opens each release as `## [X.Y.Z] - unreleased`**, starting with 2.0.0.                                                                                                                                                                                                                                                                                                                                 | devbin's default `changelog` notes kind reads that heading, not `## [Unreleased]`.                                                                                                                              |
| E8  | **No tag, push, release or tap write except in WP06**, and those are hv's. Earlier work proves the path on a scratch clone and a scratch tap.                                                                                                                                                                                                                                                                           | Outward-facing and hard to reverse.                                                                                                                                                                             |

## 3. What the binary must provide

ST0001 builds the commands; this thread needs these from the binary, built in WP03 here on ST0001's scaffold:

- the resolved root and the tree function (T1, T4);
- `install` and `use` (T2, T5) and the manifest (T3);
- the version line, with the build commit and dirtiness stamped in (T4);
- doctor lines for the tree, the manifest and the shadow check, added to ST0001's doctor;
- `handler --install` naming the opt link under brew (ST0001 WP08);
- `help --details` from the embedded README (ST0001 D6).

## 4. Migration on rhadamanth

- Today `~/.local/bin/pplr` links to the checkout's bash dispatcher. After 2.0.0, `brew install` and then `pplr use brew` remove it, and doctor's shadow check confirms brew answers.
- `setup.sh` and `.env.example` are gone (ST0001 WP13). If the user's shell configuration sets `PPLR_ROOT` or `PPLR_BIN_DIR`, or puts the checkout's `bin/` on `PATH`, that lives in Molt-matts, not here: doctor names it, and the fix is Molt-matts'.
- The People tree is not touched by any of this.
