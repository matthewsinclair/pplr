# ST0001: Port Pplr from shell scripts to Rust

## Objective

Replace Pplr's bash scripts, Python helpers and run-time-compiled Swift engine with one Rust binary, `pplr`, that serves every command the shell version offers today with the same arguments and flags, and reads and writes the People tree byte for byte as the legacy code does. It ships no Python. It keeps live Contacts access through a thin Swift I/O sidecar built ahead of time. The existing bats suite, made safe and honest first, proves it on macOS and Linux.

## Context

**Why now.** hv wants Pplr as a Rust CLI installed through Homebrew (ST0002). The shell version cannot be: it compiles its Swift engine at run time into the checkout, it needs `PPLR_ROOT`, and its handler bakes in a checkout path. It also ships Python, which the user-scope rules forbid, and its CI has been a false green.

**hv's rulings, 2026-11-02.** The Python goes, all of it. The core is Rust. Swift is acceptable where Contacts needs it, because it is already written. The test suite is to be cleaned up, not trusted.

**What is there** (the attached `recon.md` has the detail):

- bash: the dispatcher and 30 commands, 2,442 lines.
- Swift: a 1,681-line engine that holds the people model, the `pplr://` markers, `resolve`, `links` and all of the Contacts sync logic.
- Python: four helpers (tags, contact cadence, the plan workbook, the email listing), 1,030 lines.
- Tests: 99 black-box bats tests.
- The last CI run reported success with 9 tests failing on macOS and 41 on Ubuntu, because the runner exits with `rm`'s status. The test teardown can also delete whatever an inherited `PPLR_TEST_DATA` names.
- Gtools reads the same People tree through `PPLR_DIR` and `PPLR_DATA`.

**How** (the attached `design.md` has the decisions D1 to D10, the module map and the rules):

- One Rust core, with Contacts behind a store interface: a JSON store for the tests and a Swift sidecar cut down to I/O for the live store.
- A fallback, so the bats suite stays green against the Rust binary at every step, and each command has one live implementation at a time.
- Goldens captured from the legacy code, so every data file stays byte-identical.
- Cldr's house style.
- 13 work packages split between dc (the safety, scaffold, Contacts and doctor groundwork) and cc (the port).

**Inputs.** dc's boot findings and cc's survey, in vc's inbox at 2026-11-02 07:37Z and 07:38Z.

**Related.** ST0002 ships this binary through Homebrew under devbin's dev/opt/brew contract. The install layout is the seam between them: ST0001 WP02 and ST0002 WP01, both dc's.
