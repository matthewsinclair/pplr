# WP-14: pplr's own mail reader

## Objective

Give pplr its own read-only mail reader, so that `pplr email` and `contact log --email` work with no dependency on Geodica's `mail-recent`. Its JSON output becomes a stable contract that other tools, Gtools among them, can call.

**Why** (hv, 2026-11-02): reading recent mail is generally useful, so pplr should own it rather than depend on a private estate script. Once it is done, Gtools can call pplr for it.

**Where it lives: Rust, not Swift.** Mail.app has no public framework for reading a mailbox. `mail-recent` reads Mail's own SQLite files, `~/Library/Mail/V10/MailData/Envelope Index` and `~/Library/Accounts/Accounts4.sqlite`. Rust reads SQLite read-only with `rusqlite`, the bundled build Cldr already uses for BusyCal's store. Swift would add a second process and nothing more. If WP work finds a reason Swift is needed after all, raise it with vc before building.

**Scope**

- **A `mail` module**:
  - opens both databases read-only and never writes;
  - reads the fields pplr uses: date, account, from, sender address, recipients (To, Cc, Bcc), subject and Message-ID;
  - takes the last N hours, or what is in the inbox now, with `--account`, `--sent` and `--limit`, as `mail-recent index` does;
  - skips junk, trash, deleted, drafts, spam and bin, and messages marked deleted;
  - deduplicates by Message-ID.
- **The private schema**: Mail's Envelope Index schema is Apple's and unversioned, so every query lives in one module. That module checks the tables and columns it needs and refuses by name when they differ, rather than returning wrong rows.
- **Access**: reading needs Full Disk Access for the terminal running pplr. Without it, `pplr email` exits non-zero naming the setting, and doctor shows the same row.
- **`pplr email recent|inbox`**: today's numbered listing and its cache in `PPLR_CACHE_DIR`. `contact log --email N` and `contact log --email <Message-ID>` come off hold and complete WP07.
- **`pplr email --json`**: the stable contract. It is a versioned document carrying `schema` and the fields above. Its exit codes are documented: 0, 1 for no access or a schema mismatch, 2 for usage. This is what Gtools calls.
- **Tests** run against a synthetic SQLite fixture built in the test, holding only the tables and columns the module reads. They never touch a real mail store. One `#[ignore]` test reads the live store on rhadamanth on demand, read-only.
- Delete `bin/pplr_email` and `src/pplr-email/email_list.py`.

**Criteria**: AC-14.1 and AC-14.2.

**Depends on**: WP04 and WP07.

**Not in scope**: changing Gtools. Pointing Gtools at `pplr email --json` is Gtools' own work, done after this WP lands.
