# WP-01: Test safety, the parity seam and an honest runner

## Objective

Make the bats suite safe to run anywhere, honest about failure, and able to test either implementation. Then record what it says about the legacy code today.

**Scope**

- Each test keeps its data under `$BATS_TEST_TMPDIR`. No path taken from the environment, `PPLR_TEST_DATA` or any other, is ever a deletion target.
- One setting chooses the implementation under test (name it here, eg `PPLR_UNDER_TEST=<path to a pplr executable>`), defaulting to the checkout's `bin/pplr`. `setup()` stops resetting `PPLR_BIN_DIR`.
- `tests/run_tests.sh` exits with bats' status and deletes nothing it did not create. The tests generate the files they need under `tests/fixtures/` (`.cache/email-last.json`, `.mock_bin/claude`, `.mock_home/`) per test, and those files are no longer tracked.
- `.github/workflows/test.yml` fails when a test fails. WP02 replaces this workflow, so keep the fix minimal.
- **Baseline against the legacy code**:
  - on rhadamanth, through the bats lane (`intent estate slots`);
  - on CI, for both runners.
  - Record ok, not ok and skipped per runner on this thread, with a one-line triage per failing test: a legacy defect, an environment gap (eg no `uv` in CI) or a test defect.
  - The last CI run already shows, on macOS, the 7 contact tests, test 21 (`doctor --fix`) and test 33 (`new` directory structure); on Ubuntu, those plus test 41 and every test that needs the Contacts framework.

**Criteria**: AC-01.1 to AC-01.4.

**Not in scope**: fixing the legacy defects the baseline finds. They are triaged, and the port either inherits the test or the triage says why not.

**Hand-off**: cc's WP03 uses this harness, and WP02's gates run the suite through the seam.
