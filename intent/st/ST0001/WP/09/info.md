# WP-09: The Contacts store and the Swift I/O sidecar

## Objective

Put every Contacts read and write behind one store interface: a JSON store for tests and Linux, and, for the live store, the existing Swift cut down to an I/O sidecar built ahead of time.

**Scope**

- **`contacts/`**:
  - the `Card` model, which is the dump format;
  - the store trait: load the cards, back up, ensure the group, and apply link, card and photo writes;
  - `JsonStore`, which reads and writes `PPLR_CONTACTS_JSON` as the engine's fixture path does today;
  - `SidecarStore`.
- **The sidecar**:
  - move `main.swift` to `swift/pplr-contacts/main.swift`;
  - keep `dump`, including the cross-account id resolution, and `backup`;
  - add a `group` mode, which prints the PPLR group's id in the default container and makes the group if it is missing;
  - keep the access refusal, exit 3;
  - drop everything else as WP08, WP10 and WP11 port it.
- **Writes from Rust**: the Contacts.app scripts (link, card create and update, photo) and the `sips` TIFF step.
- **Build**:
  - in dev, devbin's build compiles the sidecar beside the binary;
  - ST0002's install puts it in the tree;
  - a missing sidecar is an error naming the step that builds it;
  - on Linux, the live store refuses by name.
- The live check (AC-09.2) is read-only: no `--apply`.

**Criteria**: AC-09.1 and AC-09.2.

**As built**: AC-09.1 is covered by AT-09.1 (fd67819, `src/contacts/sidecar.rs`), red at C2's parent d596c35. AC-09.2 rests on hv's live round trip after C11 and the live parity's run 4 (aa42c5a). The sidecar was cut to dump, backup and group in WP13's C2 (294b421).
