## Symptom

Pplr implements devbin's dev/opt/brew contract (devbin's `docs/dev-opt-brew.md`, T1 to T5 and T8) a second time, by hand, in Rust. devbin's own implementation is `lib/cmd/use` with `lib/install`, in bash. One contract has two implementations, and they already differ, so a maintainer meets a different switch in each tool, and every fix has to be made twice.

## The differences already there

(a) The opt prefix. Pplr takes it from `--prefix` or the environment variable `PPLR_OPT_PREFIX` (`src/config.rs:23-24` and `:74`; `src/cli.rs:85`). devbin reads its config key `install.prefix` from its own config (devbin's `bin/.devbin/config.yaml:24-25`, read at `lib/cmd/use:167-169`).

(b) `use dev`. Pplr points the link at `target/release/pplr`, a build product found through `CHECKOUT`, the path `env!("CARGO_MANIFEST_DIR")` compiles into the binary (`src/install.rs:22` and `:387-397`). devbin points it at the checkout's `bin/devbin`, and refuses `use dev` and `use opt` outside the dev checkout (`_use_in_checkout`, `lib/cmd/use:113-119`, called at `:162` and `:166`).

(c) The refusals. Pplr's `use opt` and `use brew` refuse in different cases and words from devbin's (`src/install.rs:399-416` and `Links::to_brew` at `:520-561`, against devbin's `lib/cmd/use:165-204`).

## Severity

Medium. It is a consistency and maintenance defect, with no data or security risk: a maintainer meets a different switch in each tool, and every fix has to be made twice.

## Fix outline

`pplr install` and `pplr use` go entirely, rather than being made to match devbin's. The publish and the switch are `bin/devbin install` and `bin/devbin use [dev|opt|brew]`, run in Pplr's checkout, from devbin's core once a devbin release carries devbin#0326, with Pplr declaring only its link set and its opt prefix in its config. The binary keeps only the version line (T4), from the core's stamp, and Pplr's own stamp (`build.rs`, which stamps only `PPLR_SOURCE_COMMIT` and `PPLR_SOURCE_DIRTY`) and its tree code in `src/install.rs` go.

`pplr doctor` reads that code: `install_rows` (`src/doctor.rs:103-176`) checks the tree, the manifest against its files (T3), the version line (T4) and the link's shadow check (T5), and `signatures` (`:190-235`) picks its check by tree. Those rows change with it.

## Acceptance

- `pplr install` and `pplr use` are gone. `bin/devbin install` and `bin/devbin use [dev|opt|brew]`, run in Pplr's checkout, publish Pplr's opt tree and switch its link, from the one implementation in devbin's core.
- Pplr's version line (T4) comes from the core's stamp, and Pplr's `build.rs` and the tree code in `src/install.rs` are gone.
